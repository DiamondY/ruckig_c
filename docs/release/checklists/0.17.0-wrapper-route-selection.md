# 0.17.0 Wrapper Route Selection Checklist

This checklist records the docs-only wrapper route-selection slice. It keeps
Python and Rust wrappers prototype-only and does not implement wrapper
stabilization, publish packages, change the public C ABI, add package-manager
recipes, or change release state.

## Scope

- [x] Added `docs/design/0.17.0_wrapper_route_selection.md`.
- [x] Compared continued prototype-only, Python-first
  external-installed-library, Rust-first, and dual-wrapper routes.
- [x] Selected continued prototype-only as the default route.
- [x] Did not publish a Python wheel, Rust crate, source distribution, or
  package-manager recipe.
- [x] Did not change C, Python, or Rust implementation files.

## Route Decision

- [x] Continue prototype-only is the selected default.
- [x] Python-first remains a future candidate only after shared-library
  discovery, C ABI mismatch behavior, wheel ownership, CI matrix, and release
  ownership are accepted.
- [x] Rust-first remains a future candidate only after crate linking/build
  policy, version compatibility, crate ownership, CI matrix, and release
  ownership are accepted.
- [x] Dual-wrapper stabilization remains deferred unless the doubled CI,
  release, and support burden is explicitly accepted.
- [x] Future wrapper implementation requires a separate route-specific slice.

## Boundaries

- [x] No public C header change.
- [x] No public symbol allowlist or exception change.
- [x] No workflow, version metadata, tag, or GitHub Release change.
- [x] No update to `original/ruckig-main`.
- [x] No visualization asset change.
- [x] No default heavy random, coverage, performance, or static analyzer CI
  gate change.
