# Ruckig C 0.14.0-alpha.2 Future Interrupt Surfaces Checklist

This checklist records the local `0.14.0-alpha.2` design-only evidence slice
on the `0.14.0-design - Unreleased` line. It is a quasi-spec for possible
future interrupt surfaces, not an implementation, readiness gate, or stable
release closeout.

## Scope

- [x] Current stable release remains `v0.13.0`.
- [x] `0.13.1` remains reserved for emergency `v0.13.0` patch fixes only.
- [x] Current `main` remains `0.14.0-design - Unreleased`.
- [x] `0.14.0-alpha.1` remote CI evidence remains deferred by decision; this
  slice does not push the alpha.1 local commit.
- [x] The slice is limited to future design documentation for no-waypoint
  interruption and online tracking interruption.
- [x] No C source, CMake, public header, ABI allowlist, workflow,
  package-manager file, `original/ruckig-main`, or visualization asset is
  changed.
- [x] No public C ABI, public header signature, public struct layout, enum
  numeric value, result-code numeric value, or exported symbol is added.
- [x] No version bump, tag, GitHub Release, remote push CI wait, or manual
  release-random workflow is part of this alpha design slice.

## Design Decisions Recorded

- [x] Added `docs/design/future_interrupt_surfaces.md`.
- [x] The document is a quasi-spec but explicitly marks the future semantics as
  not implemented and not approved as active runtime behavior.
- [x] No-waypoint future interruption uses the existing
  `interrupt_calculation_duration` field and only checks at complete target
  trajectory boundaries.
- [x] No-waypoint future interruption does not pause root/profile solving, does
  not reuse the waypoint engine, and does not promise true-resume.
- [x] Existing incumbent trajectory sampling is the recommended safe online
  fallback when a future no-waypoint budget expires at a complete trajectory
  boundary.
- [x] Online tracking future interruption is limited to
  `ruckig_tracking_update` and `ruckig_tracking_update_with_lookahead`.
- [x] Tracking future interruption checks only at complete tracking candidate
  or lookahead candidate boundaries.
- [x] `ruckig_tracking_calculate_sequence` remains deferred until a separate
  public diagnostics/API decision because the current sequence output has no
  API-neutral interruption carrier.
- [x] Future acceptance gates require focused C selectors, budget matrices,
  incumbent-preservation checks, allocation guards, duration-enabled coverage,
  and ABI/export guards before implementation can be accepted.
