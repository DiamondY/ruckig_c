# Ruckig C 0.4.2 Release Checklist

This checklist records the `v0.4.2` original parity coverage and evidence
closeout. `0.4.2` does not add public C API. It keeps the `v0.4.0` waypoint
aware C surface stable while recording original parity coverage estimates,
tracking design preparation, and interrupt-duration design boundaries before
the `0.5.0-design` tracking line.

## Scope

- [x] Version is `0.4.2` in `CMakeLists.txt`.
- [x] Version macros in `include/ruckig_c/ruckig.h` are `0.4.2`.
- [x] `CHANGELOG.md` has a dated `0.4.2` release entry.
- [x] `README.md` describes `v0.4.2` as the current `0.4.x` coverage/evidence
  closeout release.
- [x] `docs/current/roadmap.md` records `0.4.2` as a patch release, not a
  feature-expansion release.
- [x] Existing `v0.4.1` public functions are not removed or signature-changed.
- [x] No public C functions are added in `0.4.2`.
- [x] Existing enum numeric values and result-code numeric values are
  unchanged.
- [x] `original/ruckig-main` remains frozen as Ruckig Community `0.17.3`.
- [x] Tracking implementation, public tracking C API, soft interruption
  checkpoints, cloud/remote calculation, Pro/cloud equivalence claims, hard
  real-time waypoint guarantees, Python wheels, Rust crate publication,
  package-manager recipes, new public C API expansion, and upstream baseline
  upgrades remain deferred.

## Original Parity Coverage

- [x] `docs/current/original_parity_coverage.md` records layered coverage
  estimates and evidence links.
- [x] Coverage percentages are described as engineering estimates, not formal
  line/branch/proof coverage.
- [x] Tracking is recorded as a mandatory full-original-parity gap.
- [x] C++ template/static DoF/custom vector/Eigen ergonomics are recorded as a
  product-surface difference, not a C runtime blocker.
- [x] The matrix explains why `v0.4.2` cannot claim complete original product
  parity.

## Tracking Design

- [x] `docs/design/tracking_interface.md` records that the frozen Community
  baseline has README/examples but no local `trackig.hpp` source.
- [x] `0.4.2` does not add tracking public symbols.
- [x] `0.5.0-design` is the implementation target for tracking.
- [x] Tracking evidence strategy uses local invariants, fixed examples,
  lag/error metrics, and constraint sampling.
- [x] Optional Pro/cloud samples are non-blocking evidence only.

## Interrupt Duration Policy

- [x] `docs/design/interrupt_calculation_duration.md` documents storage-only
  behavior for `0.4.x`.
- [x] `0.4.2` does not implement optimizer interruption checkpoints.
- [x] `0.4.2` does not claim hard or soft real-time waypoint optimization.
- [x] Future interruption work requires explicit timeout/fallback semantics and
  tests.
