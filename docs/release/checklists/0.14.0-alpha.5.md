# Ruckig C 0.14.0-alpha.5 Online Tracking Interrupt Checklist

This checklist records the local `0.14.0-alpha.5` implementation slice on the
`0.14.0-design - Unreleased` line. It adds API-neutral online tracking
candidate-boundary interruption and is not readiness or stable release
closeout.

## Scope

- [x] Current stable release remains `v0.13.0`.
- [x] `0.13.1` remains reserved for emergency `v0.13.0` patch fixes only.
- [x] Current `main` remains `0.14.0-design - Unreleased`.
- [x] No public C ABI, public header signature, public struct layout, enum
  numeric value, result-code numeric value, or exported symbol is added.
- [x] No public tracking interruption diagnostics are added.
- [x] No version bump, tag, GitHub Release, remote push CI wait, or manual
  release-random workflow is part of this alpha implementation slice.

## Implemented Behavior

- [x] `ruckig_tracking_update` and
  `ruckig_tracking_update_with_lookahead` now honor
  `interrupt_calculation_duration` in Optimized mode at complete tracking
  candidate boundaries.
- [x] The tracking interrupt check is owned by the tracking layer. Internal
  no-waypoint `ruckig_update` calls still receive cleared interrupt fields, so
  no-waypoint and tracking interruption semantics do not stack.
- [x] Fast mode keeps the existing single-candidate behavior and does not
  report interruption for the accepted single complete candidate.
- [x] Optimized mode publishes the best complete candidate evaluated so far
  when budget expires, sets `was_calculation_interrupted=true`, and keeps
  diagnostics limited to candidates actually evaluated.
- [x] `ruckig_tracking_calculate_sequence` remains deferred and explicitly
  does not use tracking interruption.
- [x] Online tracking interruption does not activate waypoint resume state and
  does not use waypoint optimizer cursors.
