# Ruckig C 0.4.1 Release Checklist

This checklist records the `v0.4.1` deep stabilization release closeout.
`0.4.1` does not add public C API. It keeps the `v0.4.0` waypoint-aware C
surface stable while deepening local waypoint optimizer evidence, waypoint
performance trend coverage, and prototype wrapper smoke.

## Scope

- [x] Version is `0.4.1` in `CMakeLists.txt`.
- [x] Version macros in `include/ruckig_c/ruckig.h` are `0.4.1`.
- [x] `CHANGELOG.md` has a dated `0.4.1` release entry.
- [x] `README.md` describes `v0.4.1` as the current `0.4.x` stabilization
  release.
- [x] `docs/current/roadmap.md` records `0.4.1` as deep stabilization, not a
  feature-expansion release.
- [x] Existing `v0.4.0` public functions are not removed or signature-changed.
- [x] No public C functions are added in `0.4.1`.
- [x] Existing enum numeric values and result-code numeric values are
  unchanged.
- [x] `original/ruckig-main` remains frozen as Ruckig Community `0.17.3`.
- [x] Cloud/remote calculation, Pro/cloud numerical equivalence claims, hard
  real-time waypoint guarantees, Python wheels, Rust crate publication,
  package-manager recipes, new public C API expansion, and upstream baseline
  upgrades remain deferred.

## Waypoint Deep Stabilization Evidence

- [x] Fixed waypoint corpus now includes 1D, 2D, 4D, and 8D cases.
- [x] Fixed waypoint corpus covers tight global and per-section position
  bounds.
- [x] Fixed waypoint corpus covers per-section min/max velocity, min/max
  acceleration, max jerk, and per-section minimum duration together.
- [x] Fixed waypoint corpus covers disabled DoFs with waypoints.
- [x] Fixed waypoint corpus covers nonzero current/target boundary velocity
  with intermediate waypoints.
- [x] Waypoint sampling checks verify intermediate-duration ordering and
  waypoint section selection.
- [x] Per-section interior sampling checks position, velocity, acceleration,
  and jerk limits.
- [x] `position_extrema` and `first_time_at_position` are checked across
  multi-section trajectories.
- [x] Optimizer quality checks keep accepted durations no worse than the
  zero-derivative segment baseline where that baseline is feasible.
- [x] Section-level oracle tests remain based on the frozen original target
  solver.
- [x] Optional cloud/Pro black-box comparison evidence is not used and is not a
  runtime, CI, or release dependency.

## Interrupt Duration Policy

- [x] `interrupt_calculation_duration` remains a storage/API-surface parity
  field.
- [x] `0.4.1` does not implement optimizer interruption checkpoints.
- [x] `0.4.1` does not claim hard or soft real-time waypoint optimization.
- [x] Future interruption work requires separate design for tiny budget, no
  budget, best-feasible fallback, no-feasible-candidate fallback, and online
  previous-best reuse.
