## Readiness Findings

- [x] No-waypoint `ruckig_update` can be implemented API-neutrally as a
  complete-trajectory-boundary interruption policy. The insertion point is the
  no-waypoint changed-input path in `ruckig_update`, using the existing
  `interrupt_calculation_duration` field and `was_calculation_interrupted`
  output flag.
- [x] No-waypoint interruption must not implement true-resume. It should use
  private scratch trajectory storage for a full target solve, publish only
  complete candidates, preserve a valid incumbent when budget expires at the
  boundary, and leave no no-waypoint resume cursor.
- [x] Public `ruckig_calculate` remains a complete solve. It must continue to
  clear waypoint resume state and ignore the interrupt budget for both
  waypoint and no-waypoint inputs.
- [x] Online tracking can be implemented API-neutrally for
  `ruckig_tracking_update` and `ruckig_tracking_update_with_lookahead` by
  checking budget only at complete candidate boundaries.
- [x] Optimized online tracking should publish the best complete candidate
  evaluated so far when budget expires, set `was_calculation_interrupted`, and
  keep diagnostics limited to candidates actually evaluated.
- [x] Fast tracking may keep the existing single-candidate behavior and should
  not report interruption unless a future implementation stops useful
  retryable work early.
- [x] `ruckig_tracking_calculate_sequence` remains deferred. The current
  sequence output has no API-neutral interruption carrier equivalent to
  `ruckig_output_t::was_calculation_interrupted`.
