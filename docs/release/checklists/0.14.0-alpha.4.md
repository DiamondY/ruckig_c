# Ruckig C 0.14.0-alpha.4 No-Waypoint Interrupt Checklist

This checklist records the local `0.14.0-alpha.4` implementation slice on the
`0.14.0-design - Unreleased` line. It adds API-neutral no-waypoint
complete-trajectory-boundary interruption and is not readiness or stable
release closeout.

## Scope

- [x] Current stable release remains `v0.13.0`.
- [x] `0.13.1` remains reserved for emergency `v0.13.0` patch fixes only.
- [x] Current `main` remains `0.14.0-design - Unreleased`.
- [x] No public C ABI, public header signature, public struct layout, enum
  numeric value, result-code numeric value, or exported symbol is added.
- [x] No version bump, tag, GitHub Release, remote push CI wait, or manual
  release-random workflow is part of this alpha implementation slice.

## Implemented Behavior

- [x] No-waypoint `ruckig_update` now honors `interrupt_calculation_duration`
  at complete target trajectory boundaries.
- [x] The no-waypoint path does not implement true-resume and stores no
  no-waypoint resume cursor.
- [x] New no-waypoint candidates are solved into private preallocated scratch
  trajectory storage before publication.
- [x] If a valid no-waypoint incumbent exists and budget expires after a
  complete target attempt, the incumbent trajectory is preserved,
  `new_calculation=false`, and `was_calculation_interrupted=true`.
- [x] If no valid no-waypoint incumbent exists and a complete first target
  candidate succeeds, the candidate is published through normal first
  calculation semantics.
- [x] Incumbents from waypoint calculations are not preserved when switching
  from waypoint input to no-waypoint input.
- [x] Public `ruckig_calculate` remains a complete solve and continues to
  ignore the interrupt budget.
- [x] Tracking remains isolated in this alpha. Tracking work inputs clear the
  interrupt field before internal no-waypoint update calls; online tracking
  interruption remains the alpha.5 scope.
