# ruckig_c 0.16.0

`0.16.0` is the stable public diagnostics release. It promotes the
`0.16.0-alpha.3` through `0.16.0-alpha.5` diagnostics implementation and the
`0.16.0-readiness` evidence into a stable release.

## Highlights

- Adds opt-in diagnostics for `validate`, `calculate`, and `update` through
  `_with_diagnostics` entry points.
- Adds getter-style public diagnostics for tracking and tracking sequence
  continuation state.
- Preserves legacy API behavior: passing `NULL` diagnostics behaves like the
  existing API, and existing result-code numeric values are unchanged.
- Keeps diagnostics stable and coarse-grained. Solver profile branches,
  waypoint branch queues, tracking candidate ordering, score internals,
  optimizer phases, and random seed/sample tooling state remain private.
- Keeps Python and Rust wrappers prototype-only. No wheel, crate, or
  package-manager recipe is published in this release.

## Public C ABI

- Public symbol count moves from the `v0.15.0` 184-symbol baseline to `190`.
- Public additions in `v0.16.0`: 6 diagnostics symbols.
- Public removals in `v0.16.0`: 0.
- Existing public function signatures, existing public struct layouts, enum
  numeric values, and result-code numeric values are unchanged.

New public symbols:

- `ruckig_diagnostics_init`
- `ruckig_validate_input_with_diagnostics`
- `ruckig_calculate_with_diagnostics`
- `ruckig_update_with_diagnostics`
- `ruckig_tracking_get_last_public_diagnostics`
- `ruckig_tracking_sequence_continuation_get_last_diagnostics`

## Diagnostics Contract

`ruckig_diagnostics_t` is caller-owned and opt-in. Callers that pass a non-NULL
diagnostics pointer initialize it with `ruckig_diagnostics_init`; a too-small
`struct_size` is rejected with `RUCKIG_ERROR_INVALID_INPUT` before the main
operation runs. Valid diagnostics writes stay within the caller-declared stable
prefix, leaving reserved fields for future ABI-compatible expansion.

The diagnostics API explains public failure classes such as invalid input,
DoF/capacity mismatch, zero limits, synchronization/calculation failure,
observable interruption, waypoint resume mismatch, and tracking/continuation
state. It does not expose private solver, profile, candidate, queue, or random
tooling internals.

## Deferred

- Wrapper stabilization and package-manager recipes remain deferred.
- Generated fixture auto-write remains deferred.
- Tracking failure shrinker remains deferred.
- Solver long-tail coverage remains limited to future oracle-backed or
  public-behavior-backed cases.
- Deeper diagnostics that expose private solver/profile/candidate/queue
  internals are not part of the public API.
