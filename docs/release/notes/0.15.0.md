# ruckig_c 0.15.0

`0.15.0` is the stable tracking sequence continuation release. It promotes the
`0.15.0-alpha.4` through `0.15.0-alpha.8` continuation API, behavior, wrapper
smoke, and hardening evidence reviewed during `0.15.0-readiness`.

## Highlights

- Added the public tracking sequence continuation C API: an opaque
  `ruckig_tracking_sequence_continuation_t` handle, lifecycle/status
  accessors, and interruptible start/resume entry points.
- Implemented Fast and Optimized sequence continuation while keeping
  `ruckig_tracking_calculate_sequence` complete-only.
- Publishes only complete sequence-step prefixes from interruptible sequence
  calls, including after repeated resume.
- Preserves Optimized candidate-boundary progress privately inside the
  continuation handle.
- Hardened continuation resume semantics by capturing the initiating
  `delta_time`, rejecting wrong-`delta_time` resume handles, and keeping output
  sequence timestamps on the captured time axis.
- Unified complete Optimized sequence evaluation and Optimized continuation
  candidate enumeration through a shared internal candidate-step engine.
- Added C example coverage plus Python cffi and Rust prototype continuation
  smoke coverage.

## Compatibility

- Public C ABI: expanded from the `v0.14.0` 172-symbol ABI to 184 symbols.
- Public additions in `v0.15.0`: 12 tracking sequence continuation symbols.
- Public removals in `v0.15.0`: 0.
- Unapproved exported symbols: 0.
- Existing public function signatures, public structs, enum numeric values,
  result-code numeric values, and diagnostics layout are unchanged except for
  the accepted continuation API additions.
- `RUCKIG_RESULT_IS_OK` is a header-only helper macro and does not add a
  dynamic library symbol.
- Python `cffi` and Rust wrapper work remain prototype evidence only; no wheel
  or crate is published.
- `original/ruckig-main` remains frozen as Ruckig Community `0.17.3`.
