# ruckig_c 0.4.0

`0.4.0` is the first original-surface parity release after the `v0.3.0`
hardening line. It intentionally expands the public C ABI for local waypoint
optimization, per-section constraints, global position bounds, and
multi-section trajectory queries.

## Highlights

- Added waypoint-aware constructors for `ruckig_t`, `ruckig_input_t`,
  `ruckig_output_t`, and `ruckig_trajectory_t`.
- Added public C ABI access to global max/min position bounds.
- Added intermediate waypoint set/get/clear APIs.
- Added per-section max/min velocity, max/min acceleration, max jerk,
  max/min position, and per-section minimum-duration APIs.
- Added interrupt-calculation-duration storage APIs for original API surface
  parity. The value is recorded; this release does not guarantee soft
  interruption checkpoints in the optimizer.
- Added multi-section trajectory metadata APIs for section count and
  intermediate durations.
- Added deterministic local `ruckig_filter_intermediate_positions`.
- Added a local coupled waypoint optimizer. It searches shared internal
  waypoint velocity/acceleration candidates, evaluates every complete
  candidate through the existing target-solver section evaluator, rejects
  constraint violations, explores a deterministic internal branch queue, and
  selects the lowest-duration feasible result found.
- Added C examples for waypoint offline calculation, waypoint online updates,
  per-section minimum duration, per-section limits, intermediate-position
  filtering, and dynamic DoFs with waypoints.
- Added Python `cffi` and Rust wrapper prototypes over the `0.4.0` C ABI.

## Deferred

- Cloud and remote calculation are not implemented.
- No formal Ruckig Pro/cloud global numerical equivalence claim is made.
- No hard real-time guarantee is made for waypoint optimization.
- Python wheels are not published.
- Rust crate publication is deferred.
- Package-manager recipes are deferred.
- Upstream baseline upgrade is deferred; `original/ruckig-main` remains frozen
  as Ruckig Community `0.17.3`.
