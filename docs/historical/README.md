# Historical Documentation

This directory and the historical release records under `docs/release/` are
retained for traceability. Historical documents are not active planning inputs
unless a current roadmap or release checklist explicitly links to them.

## Maintenance Policy

- Keep historical release checklists and evidence files in place.
- Do not move, delete, or merge old release checklists merely to reduce file
  count.
- Treat `v0.1.x` through `v0.15.x` release-line records as frozen historical
  evidence.
- Update historical records only for broken links, factual release errors,
  security-relevant corrections, or explicit current-line references.
- Prefer current summary documents and index entries for new planning work
  instead of editing many historical files.

## Active Documentation Lines

The active maintained documentation lines after `v0.16.0` are:

- `v0.16.0` stable public diagnostics release records.
- `0.17.0` wrapper readiness, decision, and package policy design records.
- Post-`v0.16.0` event-driven maintenance records.

All older release evidence remains available as audit history.
