# 0.5.0 Release Decision Record

This document records the accepted release-scope decision after the
`0.5.0-design` tracking alpha cycle and the `0.5.0-alpha.2` hardening pass.
It is retained as the scope record for the stable `v0.5.0` release.

## Decision

`v0.5.0` is released with local `Fast` tracking only.

`RUCKIG_TRACKING_OPTIMIZED` remains part of the public C ABI for shape parity,
but it returns `RUCKIG_ERROR_UNSUPPORTED`. Implementing `Optimized` tracking is
deferred to `0.6.0-design`, not `0.5.x`, and must not be aliased to Fast.

## Included in `v0.5.0`

- Public C tracking ABI added during `0.5.0-design`.
- Local Fast online tracking with deterministic constant-acceleration
  lookahead.
- Local Fast offline tracking over `ruckig_target_state_sequence_t` into
  `ruckig_tracking_output_sequence_t`.
- Tracking examples for online ramp, online constant-acceleration, and offline
  sequence use.
- Local deterministic tracking evidence:
  - API lifecycle and validation tests.
  - Online and offline tracking tests.
  - Fixed corpus tests.
  - Tuned ramp and constant-acceleration quality gates.
  - Sinus and mixed-signal trend metrics without a hard quality gate.
  - No-allocation smoke for prepared tracking paths.
  - Python `cffi` prototype smoke.
  - Rust alpha wrapper smoke.
- Existing no-waypoint oracle, waypoint optimizer, ABI/export, consumer, and
  performance gates remain in scope.

## Excluded from `v0.5.0`

- `Optimized` tracking implementation.
- Soft interruption checkpoints or timeout fallback semantics.
- Released Python wheels or a formal Python API stability promise.
- Published Rust crate or a formal Rust API stability promise.
- Package-manager recipes.
- Cloud or remote calculation.
- Pro/cloud numerical equivalence claims.
- Upstream baseline upgrade.

## Quality Gate Interpretation

The release quality gate compares local Fast tracking against naive instantaneous
target chasing under the recorded lag metric.

- Ramp and constant-acceleration cases are hard-gated only for selected Fast
  configurations recorded in the tests and evidence.
- Sinus and mixed target signals are trend metrics only until a separate
  threshold decision is approved.
- The default `look_ahead_cycles = 1` remains the API default. The quality
  evidence must state the selected `reactiveness` and `look_ahead_cycles`
  being measured.

## Release Closeout Requirements

Before tagging a stable `v0.5.0`, the release checklist must record:

- Final commit hash.
- CI run id and success conclusion.
- Public header diff against `v0.4.2`.
- Public symbol count and exported-symbol comparison.
- Tracking CTest summary, including fixed corpus and quality gate output.
- Python prototype smoke summary.
- Rust alpha wrapper smoke summary.
- Existing no-waypoint oracle and waypoint gates.
- Deferred items exactly as listed above.

No `v0.5.0-alpha.2` prerelease tag or GitHub prerelease was required for the
hardening checkpoint. The stable `v0.5.0` tag is created only during release
closeout.
