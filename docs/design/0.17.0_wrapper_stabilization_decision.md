# 0.17.0 Wrapper Stabilization Decision

This is a docs-only decision record after the post-`v0.16.0` wrapper public
diagnostics prototype smoke and consumer install refresh slices. It does not
publish Python wheels or a Rust crate, does not change the C ABI, and does not
promote either wrapper from prototype status.

## Decision

Continue prototype-only wrapper status for now.

The Python and Rust prototypes now exercise the stable `v0.16.0` public
diagnostics C API, but that evidence is not sufficient to start a stable
wrapper implementation or publication line. The remaining blockers are
packaging and ownership decisions, not basic API reachability.

Accepted conclusions:

- Python remains a `cffi` ABI-mode prototype under `bindings/python_prototype/`.
- Rust remains an unpublished alpha wrapper under `bindings/rust/`.
- No Python wheel, source distribution, or stable import namespace is accepted.
- No Rust crate publication, crate name, or semver policy is accepted.
- No package-manager recipe is added.
- No public C ABI or public header change is part of this decision.

## Evidence Reviewed

- `post-v0.16.0-wrapper-public-diagnostics-prototype-smoke` added minimal
  Python/Rust prototype mappings for `ruckig_diagnostics_t`,
  validate/calculate/update diagnostics calls, tracking public diagnostics,
  and tracking sequence continuation diagnostics.
- `post-v0.16.0-consumer-install-and-docs-refresh` verified minimal public
  diagnostics usage through installed CMake and pkg-config consumer smoke
  sources.
- `v0.16.0` remains the current stable C ABI baseline with 190 public symbols.

## Criteria Status

The wrappers do not pass the stabilization criteria from
`0.17.0_wrapper_stabilization_readiness.md`:

| Criterion | Status |
| --- | --- |
| Shared/static library discovery across Windows, Linux, and macOS | Not accepted |
| Wheel/crate package contents and ownership | Not accepted |
| C ABI version compatibility and unsupported-version behavior | Not accepted |
| Diagnostics enum/result mapping for stable wrappers | Prototype evidence only |
| Lifecycle and array handling documentation | Partial prototype evidence |
| CI matrix for package paths | Not accepted |
| Release checklist for publication artifacts | Not accepted |

## Next Allowed Decisions

A later wrapper implementation plan must explicitly choose one of:

- Python-first stabilization after accepting wheel/shared-library policy.
- Rust-first stabilization after accepting crate/linking policy.
- Dual-wrapper stabilization after accepting ownership and CI cost for both.
- Continued prototype-only status.

Until one of those choices is accepted, wrapper work is limited to prototype
smoke evidence and maintenance that does not alter the public C ABI.

## Non-Goals

- No stable Python wrapper API.
- No stable Rust wrapper API.
- No wheel or crate publication.
- No public C ABI expansion.
- No edit to `include/ruckig_c/ruckig.h`.
- No ABI allowlist or public-symbol exception change.
- No version metadata, tag, GitHub Release, or workflow change.
- No package-manager recipe.
- No default heavy random, coverage, performance, or static analyzer CI gate.
