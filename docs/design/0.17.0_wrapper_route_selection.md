# 0.17.0 Wrapper Route Selection

This is a docs-only route-selection record for possible future Python or Rust
wrapper stabilization. It does not implement wrapper changes, publish packages,
change the public C ABI, or add package-manager recipes.

## Decision

Continue Python and Rust as prototype-only wrappers.

The `0.17.0-wrapper-package-policy-design` record identified the package and
discovery blockers for any stable wrapper line. Those blockers are still open:
shared-library discovery, C ABI version compatibility, package artifact
ownership, CI matrix, and release ownership have not been accepted for either
wrapper.

The post-`v0.16.0` wrapper diagnostics smoke proves that both prototypes can
exercise the stable C diagnostics API. It is readiness evidence, not a stable
wrapper API or publication decision.

## Route Comparison

| Route | Status | Required acceptance before implementation |
| --- | --- | --- |
| Continue prototype-only | Selected default | Keep existing smoke tests and documentation current; no package publication commitment. |
| Python-first external-installed-library | Viable future candidate | Shared-library search order, missing-library diagnostics, exact C ABI version mismatch behavior, wheel/source distribution ownership, supported platform matrix, and release checklist owner. |
| Rust-first | Viable future candidate | Crate linking/build policy, external or vendored library ownership, C ABI compatibility behavior, crate metadata/versioning policy, supported platform matrix, and release checklist owner. |
| Dual-wrapper stabilization | Deferred high-cost candidate | All Python and Rust requirements plus accepted doubled CI, release, and support burden. |

## Selected Default: Continue Prototype-Only

The selected default keeps the current repository behavior:

- no Python wheel;
- no Rust crate publication;
- no stable Python or Rust wrapper API;
- no package-manager recipes;
- no public C ABI expansion;
- no workflow or release-state change.

Prototype wrappers may continue to receive smoke coverage that demonstrates the
stable C ABI, including public diagnostics. That does not convert those wrapper
methods into stable package APIs.

## Future Implementation Gate

A future wrapper implementation slice must explicitly choose one route:

- Python-first stabilization;
- Rust-first stabilization;
- dual-wrapper stabilization;
- continued prototype-only status after renewed review.

The implementation slice must also record accepted owners for package artifacts,
shared-library or static-link discovery, C ABI version compatibility, CI, and
post-release support before code changes start.

## Non-Goals

- No wrapper implementation change.
- No package publication.
- No public C header change.
- No ABI allowlist or public-symbol exception change.
- No workflow, version metadata, tag, or GitHub Release change.
- No package-manager recipe.
- No update to `original/ruckig-main`.
