# 0.16.0 Design Readiness

Status: ready to start a docs-only `0.16.0-design-public-diagnostics` line.

This readiness audit follows the post-`v0.15.0` quality closeout. It does not
implement public API, change the 184-symbol `v0.15.0` public C ABI baseline,
change version metadata, create a tag or release, publish wrappers, edit
workflows, change ABI allowlists, update `original/ruckig-main`, or touch
visualization assets.

## Current State

The `v0.15.0` stable release line has completed a broad post-release quality
series:

- State-machine, solver, solver-adjacent, residual public-boundary, and roots
  numeric fixed coverage are in place.
- Random failures can be replayed/exported by seed/sample, and the local MVP
  shrinker can emit smaller fixture-ready initializers for passing samples.
- External-review follow-up refactors are complete, including tracking split,
  private interrupt context unification, profile-check context entry points,
  roots guard cleanup, and waypoint branch-queue saturation coverage.
- Portability/static evidence covers normal/shared CTest, exported symbols,
  Windows static/DLL consumer paths through CI, and local platform-clock compile
  probes.
- Final coverage-bearing baseline is branch coverage `73.91%` at
  `out/coverage/post-v0.15.0-residual-branch-coverage/coverage-summary.txt`.

The project is no longer blocked on generic quality hardening before a new
design line. Future work should be driven by product/API decisions or concrete
regressions.

## Candidate Directions

| Candidate | Readiness | Decision |
| --- | --- | --- |
| Public diagnostics | High | Recommended first `0.16.0` design line. It would make invalid input, interruption, resume mismatch, tracking candidate, and waypoint resume failures easier to explain without relying on private test-only diagnostics. |
| Wrapper stabilization | Medium | Defer. Python/Rust smoke coverage is useful, but stable wrapper publication needs a separate surface, semver, packaging, and support-policy design. |
| Failure-oriented random shrinker | Medium | Defer as a post-release local-tool slice. It does not require public ABI and should not block diagnostics design. |
| Solver long-tail oracle-backed coverage | Low to medium | Defer unless a concrete regression or oracle-backed case appears. Remaining branch gaps should not be chased by fragile probes. |
| Package-manager recipes | Low | Keep frozen unless external distribution demand reopens the package-management decision. |

## Readiness Decision

Start `0.16.0-design-public-diagnostics` as a docs-only design line.

The design line must:

- Keep existing result-code numeric values unchanged.
- Keep existing public struct layouts unchanged.
- Prefer opt-in diagnostics accessors and new private/public boundary records
  over modifying existing handles or structs.
- List every possible new public symbol, enum, struct, result-code, and ABI
  artifact change before implementation.
- Treat Python/Rust wrappers as prototype-only until a separate wrapper
  stabilization design is accepted.
- Keep heavy random, coverage, performance, and static-analysis gates as
  local/manual evidence unless a separate CI-cost decision accepts them.

The readiness decision does not approve implementation. It only approves
creating the public diagnostics design document.
