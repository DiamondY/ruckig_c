# 0.16.0 Public Diagnostics Design

Status: docs-only design started. No API is implemented by this document.

This design starts the `0.16.0-design-public-diagnostics` line after the
post-`v0.15.0` quality closeout and readiness audit. The goal is to make public
failure and interruption behavior easier to explain without exposing unstable
private solver internals.

## Goals

- Explain common invalid-input failures with a structured reason, location,
  and relevant value or limit.
- Explain interruption and resume states for no-waypoint, waypoint, and
  tracking sequence paths.
- Provide a stable public replacement path for test-only or private diagnostic
  counters that are useful to users.
- Preserve all existing public result-code numeric values and public struct
  layouts.
- Keep diagnostics opt-in so existing users do not need code changes.

## Non-Goals

- No implementation in this design slice.
- No change to `include/ruckig_c/ruckig.h` in this design slice.
- No result-code renumbering or semantic change to `RUCKIG_RESULT_IS_OK`.
- No package-manager, release, tag, workflow, wrapper-stability, or version
  metadata change.
- No exposure of raw solver profile candidates, polynomial branch names, or
  unstable private queue internals.

## Candidate Public ABI Shape

The preferred implementation direction is a new diagnostics record with fixed
size/reserved fields, plus opt-in accessors or `_with_diagnostics` entry
points. Existing functions keep their current behavior.

Candidate new public types:

```c
typedef enum ruckig_diagnostic_scope {
    RUCKIG_DIAGNOSTIC_SCOPE_NONE = 0,
    RUCKIG_DIAGNOSTIC_SCOPE_INPUT = 1,
    RUCKIG_DIAGNOSTIC_SCOPE_CALCULATION = 2,
    RUCKIG_DIAGNOSTIC_SCOPE_UPDATE = 3,
    RUCKIG_DIAGNOSTIC_SCOPE_WAYPOINT = 4,
    RUCKIG_DIAGNOSTIC_SCOPE_TRACKING = 5,
    RUCKIG_DIAGNOSTIC_SCOPE_TRACKING_SEQUENCE = 6
} ruckig_diagnostic_scope_t;

typedef enum ruckig_diagnostic_code {
    RUCKIG_DIAGNOSTIC_NONE = 0,
    RUCKIG_DIAGNOSTIC_NULL_ARGUMENT = 1,
    RUCKIG_DIAGNOSTIC_DOF_MISMATCH = 2,
    RUCKIG_DIAGNOSTIC_CAPACITY_MISMATCH = 3,
    RUCKIG_DIAGNOSTIC_INVALID_ENUM = 4,
    RUCKIG_DIAGNOSTIC_NONFINITE_VALUE = 5,
    RUCKIG_DIAGNOSTIC_NEGATIVE_LIMIT = 6,
    RUCKIG_DIAGNOSTIC_ZERO_LIMIT = 7,
    RUCKIG_DIAGNOSTIC_CURRENT_STATE_OUT_OF_LIMITS = 8,
    RUCKIG_DIAGNOSTIC_TARGET_STATE_OUT_OF_LIMITS = 9,
    RUCKIG_DIAGNOSTIC_TRAJECTORY_DURATION = 10,
    RUCKIG_DIAGNOSTIC_SYNCHRONIZATION = 11,
    RUCKIG_DIAGNOSTIC_INTERRUPTED = 12,
    RUCKIG_DIAGNOSTIC_RESUME_IDENTITY_MISMATCH = 13,
    RUCKIG_DIAGNOSTIC_UNSUPPORTED = 14
} ruckig_diagnostic_code_t;

typedef struct ruckig_diagnostics {
    size_t struct_size;
    ruckig_result_t result;
    ruckig_diagnostic_scope_t scope;
    ruckig_diagnostic_code_t code;
    size_t dof;
    size_t section;
    size_t expected_count;
    size_t actual_count;
    double value;
    double limit;
    size_t reserved_size[8];
    double reserved_value[8];
} ruckig_diagnostics_t;
```

Candidate result-code policy:

- Add no new result code unless implementation proves that an existing code
  cannot represent the public failure class.
- Existing result-code numeric values remain frozen.
- Diagnostic codes refine result meaning but do not replace result codes.

## Public / Private Boundary

Public diagnostics may expose:

- Argument category, DoF index, section index, expected count, actual count,
  offending value, and relevant limit.
- Stable interruption/resume status such as interrupted, complete, identity
  mismatch, capacity mismatch, or unsupported operation.
- Stable tracking calculation status already represented by public tracking
  diagnostics.

Public diagnostics must not expose:

- Raw candidate ordering, exact private branch queue contents, polynomial
  profile branch identifiers, or solver-internal tie-break implementation.
- Allocator internals beyond public invalid-input or capacity diagnostics.
- Test-only random seed/sample metadata; replay and shrink tools remain test
  binaries, not library API.

## Compatibility And Migration

Existing users keep calling `ruckig_validate_input`, `ruckig_calculate`,
`ruckig_update`, and tracking functions unchanged. New diagnostics entry points
are opt-in and may be adopted incrementally.

If implemented, the first implementation slice must include:

- Header compile tests for C and C++ consumers.
- Public symbol allowlist update as an explicit reviewed ABI expansion.
- ABI/export comparison evidence proving only the intended symbols are added.
- Fixed tests for invalid input, zero limits, current/target limit failures,
  waypoint resume mismatch, tracking sequence resume mismatch, and interruption
  diagnostics.
- Wrapper smoke only as prototype evidence; no stable wrapper publication.
