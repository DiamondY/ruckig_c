# 0.17.0 Wrapper Stabilization Readiness

This is a docs-only readiness decision for a possible `0.17.0` wrapper
stabilization line. It does not publish Python wheels or a Rust crate, does not
change the C ABI, and does not promote either wrapper from prototype status.

## Recommendation

Use a criteria-first path. Python and Rust wrappers remain prototype-only until
the project has explicit release ownership, packaging policy, shared-library
discovery, C ABI compatibility, diagnostics mapping, and CI evidence for the
chosen wrapper surface.

No implementation slice should start by default from this document. A later
wrapper stabilization implementation plan must choose Python-first, Rust-first,
or a dual-wrapper release based on the criteria below.

## Current State

Python:

- The prototype lives under `bindings/python_prototype/`.
- It uses `cffi` ABI mode and loads an already-built shared `ruckig_c` library.
- Routine smoke coverage requires `RUCKIG_C_SHARED_LIBRARY`.
- It has no wheel metadata, source distribution, vendored shared-library
  policy, or stable Python package namespace.
- It covers the core C API, waypoint surfaces, tracking, interruption smoke,
  tracking sequence continuation, specialized tracking diagnostics, and
  prototype public diagnostics evidence for the stable `v0.16.0` C ABI.

Rust:

- The alpha wrapper lives under `bindings/rust/`.
- It links an already-built `ruckig_c` static library through `build.rs`.
- It is not published as a crate and is not installed by CMake.
- It covers the core C API, waypoint surfaces, tracking, interruption smoke,
  tracking sequence continuation, examples, specialized tracking diagnostics,
  and prototype public diagnostics evidence for the stable `v0.16.0` C ABI.
- It has no accepted crate ownership, native library discovery policy, or
  semver compatibility policy.

## Stabilization Criteria

A wrapper can enter an implementation slice only after all of these are
accepted for that wrapper:

- Shared-library or static-library discovery works on Windows, Linux, and
  macOS without relying on developer-local paths.
- Packaging policy is explicit: wheel/crate contents, vendored library policy,
  source-build fallback, license metadata, and install instructions.
- Wrapper semver policy is tied to the stable C ABI baseline and documents how
  unsupported C versions fail.
- Public diagnostics are mapped without exposing private solver, profile,
  candidate, waypoint queue, or random tooling internals.
- Ownership and lifecycle rules are documented for every opaque C handle the
  wrapper owns.
- Array/vector copy-in and copy-out behavior is documented, including length
  validation and non-finite numeric handling.
- CI builds and tests the package path on the target operating systems without
  adding heavyweight random, coverage, or static-analysis gates to default CI.
- Release checklists define smoke tests, package artifacts, version metadata,
  rollback handling, and evidence required before publication.

## Python-Specific Gaps

- Decide whether `cffi` ABI mode remains the stable implementation or whether
  a CPython extension becomes necessary.
- Decide whether wheels vendor `ruckig_c` or require an external shared
  library.
- Define Python package name, import namespace, exception hierarchy, and
  diagnostics enum/value mapping.
- Keep NumPy optional unless a separate design accepts it as a dependency.
- Preserve deterministic handle destruction, context-manager behavior, and
  after-close errors.

## Rust-Specific Gaps

- Decide crate name, ownership, license metadata, and publication process.
- Decide whether the crate links a bundled static library, discovers an
  installed library, or builds `ruckig_c` as part of the crate build.
- Define safe wrapper types around opaque handles, diagnostics enums, result
  mapping, and error handling.
- Define feature flags for static/shared linking and optional examples.
- Keep `unsafe` blocks isolated around FFI boundaries with documented
  invariants.

## Non-Goals

- No wheel or crate publication in this readiness slice.
- No public C ABI expansion.
- No change to `include/ruckig_c/ruckig.h`.
- No package-manager recipes.
- No default heavy random, coverage, or static analyzer CI gates.
- No wrapper stability claim until a later implementation and release checklist
  explicitly accepts one.

## Next Decision Gate

The next wrapper-related slice should be a design or implementation plan that
chooses one of these directions:

- Python-first stabilization after accepting wheel/shared-library policy.
- Rust-first stabilization after accepting crate/linking policy.
- Continue prototype-only if packaging ownership remains unresolved.

Until that gate is passed, both wrappers remain smoke evidence for the public C
ABI rather than stable downstream packages.
