# 0.18.0 Upstream Baseline Provenance Readiness

This is a docs-only readiness record for the provenance of the frozen upstream
Ruckig source tree under `original/ruckig-main`. It does not update the
baseline, replace source files, change oracle tolerances, or change the public C
ABI.

## Decision

Keep the current checked-in upstream tree as the `0.17.3-line frozen baseline`
for ordinary maintenance.

This readiness slice does not formally re-label the baseline as a post-tag
snapshot and does not wait for a future upstream tag before recording the
current provenance risk. The point is to make the accounting issue explicit
while keeping source and oracle behavior frozen.

## Current Facts

- Readiness was prepared from `main` at `5732b9c Record documentation
  maintenance freeze`.
- `original/ruckig-main` is a tracked source tree in this repository, not an
  independent submodule or Git checkout.
- `original/ruckig-main/CMakeLists.txt` still declares
  `project(ruckig VERSION 0.17.3 LANGUAGES CXX)`.
- `docs/current/upstream_delta_audit.md` records that upstream has no newer
  public tag than `v0.17.3`, while upstream HEAD contains post-tag commits.
- The latest observed upstream HEAD remains
  `f48cf5fe8c48083b88b7ceda9a069dd5565d0d38`, described by a temporary audit
  clone as `v0.17.3-7-gf48cf5fe8c48`.

## Problem Definition

This is a provenance and accounting problem, not a solver upgrade problem.

The current frozen tree can continue to serve as the oracle baseline for
ordinary maintenance. The risk is that a future maintainer may read `0.17.3` as
an exact tag identity even though the existing audit found selected local source
files matching upstream post-`v0.17.3` HEAD content when CRLF differences are
ignored.

Ordinary maintenance must therefore avoid opportunistic refreshes of
`original/ruckig-main`. Any source replacement, re-anchor, tolerance change, or
oracle corpus update remains a separate upstream baseline project.

## Routes Considered

| Route | Decision | Rationale |
| --- | --- | --- |
| Keep current frozen tree as-is | Recommended default | Preserves the current oracle and avoids source churn while documenting provenance risk. |
| Re-anchor when upstream publishes a newer tag | Deferred | A future tag would provide a cleaner provenance target, but no newer public tag was observed in this readiness slice. |
| Explicitly document a post-tag snapshot baseline | Not accepted in this slice | It would change the baseline identity commitment without running a full baseline upgrade project. |

## Readiness Conclusion

Do not update `original/ruckig-main` and do not formally re-label the baseline in
this slice.

The current policy remains: `original/ruckig-main` is the `0.17.3-line frozen
baseline`. This wording intentionally preserves the historical version anchor
without claiming an exact upstream tag checkout.

Open a separate `0.18.0-upstream-baseline-upgrade-readiness` slice only if one
of these triggers appears:

- Upstream publishes a newer public tag.
- A material upstream solver, C++ API, performance, or provenance delta appears.
- Oracle random/fixed tests expose a mismatch that maps to upstream behavior.
- A user reports a reproducible issue that appears fixed upstream.

## Non-Goals

- No update to `original/ruckig-main`.
- No formal post-tag snapshot baseline identity.
- No public C wrapper or ABI change.
- No source inventory replacement.
- No oracle tolerance, fixed corpus, random seed, or performance baseline change.
- No heavy random or performance run for this readiness-only slice.
