# 0.4.0 Original-Surface Parity Design

`0.4.0` is the first public C ABI expansion after the `v0.3.0` hardening
release. It targets full original-surface parity while keeping the runtime
local and keeping `original/ruckig-main` frozen as Ruckig Community `0.17.3`.

## Decisions

- Implement a local waypoint optimizer. Do not call Ruckig cloud and do not add
  a remote fallback.
- Treat the original-surface parity work as alpha evidence first. Stable
  `v0.4.0` was published only after optimizer correctness, ABI review, and
  wrapper smoke evidence were complete.
- Allow public C API additions in `0.4.0`, but do not remove or change existing
  `v0.3.0` public symbols, signatures, enum values, or result-code values.
- Use a hybrid oracle strategy. Existing no-waypoint behavior remains compared
  against the frozen C++ oracle. Waypoint behavior uses local invariants,
  fixed regression cases, section-level target-solver checks, and optional
  non-blocking cloud/Pro black-box comparison evidence when available.
- Python `cffi` expansion comes after the C ABI and local optimizer alpha are
  stable. Rust follows Python.

## Original Surface Inventory

The `0.4.0` C ABI covers these original user-facing concepts:

- waypoint-aware construction with `max_number_of_waypoints`;
- global max/min position bounds;
- intermediate positions;
- per-section max/min velocity;
- per-section max/min acceleration;
- per-section max jerk;
- per-section max/min position;
- per-section minimum duration;
- interrupt calculation duration storage;
- intermediate duration queries;
- intermediate-position filtering.

Cloud client behavior remains intentionally out of scope. The local optimizer
does not claim Ruckig Pro/cloud global numerical equivalence.

## Local Optimizer Model

The alpha optimizer is coupled across all waypoint sections. It is not a
simple independent section concatenation.

- Fixed positions are the current position, every intermediate waypoint, and
  the final target position.
- Decision variables are internal waypoint velocity and acceleration vectors.
- Current velocity/acceleration and target velocity/acceleration are fixed by
  the caller.
- A candidate is accepted only when every section is solved by the existing
  target solver and all global/per-section position bounds are respected.
- The objective is minimum total duration among feasible candidates.
- Candidate seeds include zero internal derivatives and deterministic
  finite-difference derivative estimates. A bounded coordinate refinement then
  searches around the best feasible candidate.
- A deterministic branch queue explores bounded velocity/acceleration
  perturbations around the current best candidate. Branches are ordered by an
  optimistic lower-bound estimate, while only fully validated target-solver
  section evaluations can update the accepted best trajectory.
- Per-section minimum duration is mapped to each section evaluator.

This implementation does not provide a proof of global optimality and does not
make hard real-time guarantees for waypoint optimization. It allocates all
large buffers during construction or setter calls; the prepared
calculate/update path is covered by allocation-forbidden tests.

## Validation Rules

- Intermediate waypoints require position control.
- Intermediate waypoints reject global minimum duration.
- Intermediate waypoints reject discrete duration.
- Intermediate waypoints reject per-DoF control-interface and synchronization
  overrides.
- Intermediate waypoints reject infinite jerk limits.
- Per-section vector constraints must have `waypoint_count + 1` sections.
- Max velocity, max acceleration, and max jerk must be non-negative; waypoint
  max jerk must be finite and positive.
- Min velocity and min acceleration must be non-positive.
- Min position must be less than or equal to max position.

## Alpha Acceptance

The alpha is acceptable when:

- existing no-waypoint oracle, C, ABI, consumer, sanitizer, and performance
  gates still pass;
- public symbol allowlist verification is clean;
- waypoint constructors, storage, validation, filtering, multi-section
  sampling, extrema, first-time, and intermediate durations are tested;
- the waypoint optimizer returns only feasible trajectories;
- the prepared waypoint calculate path has no runtime allocation;
- C examples demonstrate waypoint offline, waypoint online, per-section
  minimum duration, per-section limits, intermediate-position filtering, and
  dynamic DoFs with waypoints.
- focused CTest entries cover waypoint optimizer, per-section constraints, and
  waypoint quality alpha checks.
- section-level oracle tests verify accepted waypoint-generated section inputs
  against the frozen original target solver.
- the fixed waypoint corpus includes multi-DoF, multiple-waypoint,
  per-section duration/bounds, disabled-DoF, and nonzero boundary-velocity
  alpha regressions.
- deterministic branch-queue exploration is part of the local optimizer and
  remains internal; no optimizer workspaces or diagnostics are exported.
- the Python `cffi` prototype covers the new C ABI when `cffi` is available,
  while remaining outside the released binding/API scope.
- the Rust alpha wrapper covers the public C ABI through `ruckig_c` handles and
  has smoke tests and examples, while remaining outside published crate scope.
- waypoint alpha performance is recorded as a C-only local optimizer trend
  corpus because the frozen Community baseline has no local global waypoint
  optimizer.

## Stable Release Decision

Stable `v0.4.0` was published after final release-candidate local gates,
cross-platform push CI evidence, manual release-random evidence, ABI/export
review, waypoint optimizer evidence, and wrapper smoke evidence completed.
The release evidence is recorded in `docs/release/checklists/0.4.0.md`,
`docs/release/evidence/verification_report.md`, and
`docs/release/evidence/performance_report.md`.

The stable claim remains intentionally bounded: local waypoint optimizer only,
no cloud or remote calculation, no formal Ruckig Pro/cloud global numerical
equivalence claim, no hard real-time guarantee for waypoint optimization, and
prototype-only Python/Rust wrappers.
