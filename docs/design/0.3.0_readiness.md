# 0.3.0 Readiness

This document records the decision state for entering `0.3.0-design` after the
final planned `0.2.x` stabilization release. It is design guidance only. It
does not approve binding implementation, package-manager recipes, solver
changes, public C API changes, or upstream baseline upgrades.

## Baseline State

- Latest pre-`0.3.0` release: `v0.2.5`.
- Frozen upstream oracle: Ruckig Community `0.17.3` under
  `original/ruckig-main`.
- Public C ABI: stable through the `0.2.x` release evidence process.
- ABI evidence: public header diff review plus Linux and Windows
  exported-symbol comparison. `docs/abi/v0.2.5/` is the baseline for
  `0.3.0-design` comparison and any future emergency `0.2.6`.
- Linux shared-library export note: `v0.2.5` records the historical Linux
  export set, including implementation-internal `ruckig_*` symbols that were
  visible before the `0.3.0-design` export-hygiene pass. These are not public
  header API.
- Public symbol allowlist: `docs/abi/public-symbols.txt` records the approved
  public C ABI from `include/ruckig_c/ruckig.h`. Current `0.3.0-design` builds
  use hidden visibility and public-symbol comparison artifacts so binding
  prototypes and existing installed-package consumers depend on the public
  shared-library surface.
- Fixed oracle suite count: `74` at `v0.2.5`; `0.3.0-design` adds fixed
  50s and 100s exact-target first-time boundary cases, bringing the current
  fixed suite to `76`.
- Random oracle evidence: ordinary random seeds `1`, `2`, and `41` at
  `100000` samples, plus per-DoF random seed `1` at `100000` samples.
- Release random evidence: manual workflow run `26965856552`,
  `--random 1000000 --seed 1`.
- Performance baseline: Windows and Linux `--samples 10000 --seed 1`, with
  average C/oracle ratio required to be `<= 1.5`.
- Consumer evidence: installed CMake, Unix pkg-config, Unix shared
  install-tree, Windows clang static, Windows clang DLL, Windows clang-cl
  static, Windows clang-cl DLL, opt-in locally verified MSVC `cl` standalone
  static/DLL paths, and locally verified MinGW static/DLL consumer paths.

## Go/No-Go Decisions

- Python binding prototype: Go after `v0.2.5`, with `cffi` ABI mode as the
  default prototype route and the cleaned public shared-library surface as the
  loading target.
- Rust bindings: Defer until Python feasibility has clarified ownership,
  packaging, and error-model decisions.
- Package managers: downgraded to long-term optional work. Keep the existing
  installed CMake package, Unix pkg-config, Windows static/DLL, and shared
  install-tree consumption paths in scope. No package-manager recipe, new
  package-manager prototype, or package-manager release commitment is part of
  active `0.3.0-design` unless a separate packaging project is accepted. The
  existing vcpkg overlay may remain as frozen reference evidence only.
- Strict ABI diff gate: Start with public-symbol allowlist comparison in
  `0.3.0-design`. Keep local strict fail behavior opt-in while the dedicated
  Linux and Windows exported-symbol CI jobs continue in warning/evidence mode
  and upload ABI artifacts for review.
- Upstream baseline upgrade: Defer. Treat any upgrade as a separate project
  with upstream diff review, source inventory update, tolerance review, fixed
  corpus update, full random stress, and performance baseline rebuild.
- Waypoints, per-section constraints, and cloud: Defer. These require a
  separate public API design before implementation. The current hardening queue
  must not add public setters, public ABI symbols, or solver dispatch for these
  features; `RUCKIG_ERROR_UNSUPPORTED` remains a future-compatible reserved
  result code.
- `very large duration + exact target first-time-at-position`: Classified as a
  documented tolerance exception for the retained 100s fixed oracle case. The
  C implementation and frozen C++ oracle match found/not-found semantics and
  trajectory sampling, while first-time results differ by about `1.64e-4s` on
  the long near-flat final segment; the case uses a `2e-4` first-time tolerance.
- `0.2.6`: Reserve only for emergency patch work after `v0.2.5`; it is not the
  default post-release route.

## Entry Criteria For 0.3.0-design

- `v0.2.5` is published.
- Release evidence is complete in `docs/release/`.
- `docs/abi/v0.2.5/` Linux and Windows symbol baselines are saved.
- Windows and Linux performance baselines are recorded.
- The packaging matrix is documented, including locally verified opt-in MSVC
  `cl` standalone static/DLL gates and locally verified MinGW static/DLL
  consumer paths with a dedicated MSYS2 MinGW64 routine CI gate.
- Python feasibility design is complete and keeps `cffi` ABI mode as the
  default prototype route.
- `original/ruckig-main` remains frozen as the Ruckig Community `0.17.3`
  oracle baseline.

## 0.3.0-design First Priorities

1. ABI/export hygiene: maintain hidden implementation-internal symbols and
   compare current exports against `docs/abi/public-symbols.txt`.
2. Strict public ABI diff gate trial, warning/evidence-only by default.
3. Windows consumer matrix hardening for MSVC `cl` and MinGW feasibility.
4. Python `cffi` ABI-mode prototype design and prototype smoke, still
   experimental and not routine CI.
5. Upstream baseline upgrade evaluation as a separate project.
6. Rust binding feasibility after Python feasibility results.

Long-term optional and possibly frozen:

- Package-manager recipes or additional prototypes for vcpkg, Conan, Homebrew,
  FetchContent, and vendored subdirectory use.

Package-manager work can be reopened only as a separate packaging project after
public ABI comparison is stable, Windows/Linux/macOS static/shared consumer
state is explicit, MinGW/MSVC status is clear, and the CI maintenance budget is
accepted.

## Non-Goals

- No binding implementation in this readiness step.
- No package-manager recipe in this readiness step.
- No new package-manager prototype in this readiness step.
- No public C API additions.
- No solver dispatch or numerical behavior changes.
- No upstream baseline upgrade.
- No waypoint, per-section constraint, or cloud implementation.
