# 0.3.0 Release Decision

This document records the accepted release decision for `ruckig_c 0.3.0`.
It supersedes the open-ended `0.3.0-design` evaluation state, but it does not
approve new public C API, solver behavior, bindings release work,
package-manager recipes, or upstream baseline changes.

## Decision

`0.3.0` is a hardening release.

The release promotes the completed `0.3.0-design` engineering work into a
versioned release boundary. Its purpose is to publish ABI/export hygiene,
consumer-matrix hardening, remote CI evidence, macOS shared/export evidence
bootstrap, and Python binding feasibility evidence while keeping the existing
C API and solver scope frozen.

## Included Scope

- Version metadata advances from `0.2.5` to `0.3.0`.
- Public symbol allowlist verification remains a required release gate.
- Linux and Windows public exported-symbol comparison remains a strict-script
  trial in evidence mode, not a routine CI hard failure.
- Non-Windows shared builds keep hidden implementation-internal symbols.
- Linux shared builds keep the public-symbol version script.
- macOS shared/export evidence starts from `0.3.0`; no historical `v0.2.5`
  macOS baseline is invented.
- Existing installed CMake package, pkg-config, Windows static/DLL, MinGW, and
  shared install-tree consumer paths remain the supported integration surface.
- The Python `cffi` workspace remains feasibility evidence only.

## Excluded Scope

- No new `RUCKIG_C_API` public symbol.
- No public function addition, removal, or signature change.
- No enum or result-code numeric value change.
- No solver dispatch or numerical behavior expansion.
- No package-manager recipe or new package-manager prototype.
- No Python binding package, wheel, source distribution, CMake install target,
  or routine CI job.
- No Rust binding.
- No waypoint, per-section constraint, or cloud public API.
- No upstream Ruckig baseline upgrade.

## ABI Gate Decision

`ruckig_c_verify_public_symbols` may remain a hard release gate because it
compares the public header declarations against the tracked public allowlist.

Linux and Windows public exported-symbol strict comparison stays in
trial/evidence mode for `0.3.0`. The artifacts must be reviewed and recorded,
but routine CI should not fail solely because this trial script reports drift
until the exception workflow and artifact diagnostics are mature enough for a
hard gate.

## macOS Baseline Decision

`v0.2.5` has no macOS exported-symbol baseline. `0.3.0` therefore records the
first macOS shared/export snapshot as a current baseline bootstrap. Release
notes and checklists must not claim historical macOS ABI compatibility for
`v0.2.5` to `0.3.0`.

## Follow-Up Projects

The following remain independent future projects:

- Promote Linux/Windows public exported-symbol strict comparison to routine
  CI hard failure after repeated clean artifact review.
- Define a macOS historical ABI baseline policy for `0.3.x`.
- Move Python bindings from feasibility prototype to package design.
- Reopen package-manager work only after ABI, consumer matrix, and CI budget
  prerequisites are accepted.
- Evaluate Rust bindings after Python feasibility stabilizes.
- Evaluate upstream Ruckig baseline upgrades as a standalone project.
- Design waypoints, per-section constraints, and cloud behavior separately.
